# コンセプト

## 1. 目的

コンピュータネットワークの基礎から中級(一部上級)までを、2D/3Dのグラフィックとクリック・ドラッグ操作を駆使したインタラクティブな体験を通じて、能動的な実験によって理解できるWebアプリを作る。読んで覚えるのではなく、自分の手で操作して体感することで理解が身につくことを目指す。

## 2. 体験デザインの参照元

インタラクティブなStep-by-stepウォークスルー + 自由に触れるLab、という構成は `/Users/mo/Projects/ai-engineering-lab` を踏襲する。具体的には次の設計をそのまま引き継ぐ:

- **内容階層**: Module → Unit → Chapter → Section → Step
- **チャプター構成**: ガイド付きの Walkthrough(1歩ずつ進むスライド)から始まり、完了すると自由操作の **Lab(Explore it yourself)** が解放される
- **用語集**: 専門用語はクリック/タップで開く `Term` コンポーネントとして提示する(ホバーには依存しない — モバイルで動作しないため)
- **undo/reset**: ユーザーが行った操作は必ず元に戻せる
- **レイアウト順**: どの画面幅でも「タイトル → 説明 → 図」の順を守る
- **レスポンシブ**: モバイルでも使えること

## 3. 学習順序の原則

基本的に簡単なものから難しいものの順に並べるが、**厳密な難易度順よりも自然なまとまりを優先する**。関連が深い概念は、多少難易度が前後しても近くに配置してよい。

例:「通信の階層モデル(OSI/TCP-IPモデル)」は概念としては抽象的で難しいが、MACアドレス・IPアドレス・ポート番号という具体例を先に学んだ**後**に、それらを層として振り返る総まとめとして配置する方が理解しやすい。そのため本アプリの目次では、階層モデルの章をあえて基礎編の冒頭ではなく終盤に置いている。抽象的な理論を先に教科書的に並べるのではなく、「具体→抽象」の順を優先する。

## 4. トピック選定基準

扱うトピックを選ぶ・広げる際は、次の2軸で優先度を判断する:

1. **重要性** — 実務や基礎教養として役に立つか、他の章の土台になるか
2. **可視化適性** — このアプリの強みである2D/3Dのインタラクティブな操作・可視化と相性が良いか

両方を満たすトピックを最優先する。片方しか満たさない場合(例: ベンダー固有のCLI構文、BGPの自律システム間のポリシー調整のような政治的・運用的な話題は重要ではあるが可視化しても学びが深まりにくい)は、扱いを軽くする、概念の核だけに絞る、または既存の章に短いセクションとして統合するにとどめ、無理に独立した章を作らない。

## 5. 深さの基準

資格試験の合格を目的とはしない。試験特有の丸暗記事項や出題テクニックの類は扱わない。

しかし、**このアプリの内容を一通り理解していれば、日本の国家試験であるネットワークスペシャリスト試験・応用情報技術者試験のネットワーク分野の解説を読んだときに、内容として腑に落ちる程度の「仕組みレベル」の理解に到達すること**を深さの目標水準とする。「住所のようなもの」で終わるような比喩だけの説明ではなく、実際のプロトコルの動作(ハンドシェイクの手順、テーブルの中身、アルゴリズムの考え方)まで踏み込んで扱う。
