第一章（番外編改訂版）：チーズはどこへ行くか？ 〜家のルーター（LAN）を駆け抜ける最短ルート〜
ネズミくんは撮ったばかりの「特製エメンタールチーズ」の写真を、隣の部屋にあるお父さんのPCの「共有フォルダ」へ直接保存することにしました。

「LINEやメールで送ると、一度家を出て遠くのクラウドサーバーまで遠回りしちゃう。でも、同じ家の中にあるお父さんのPCの共有フォルダなら、家の中のネットワーク（LAN）だけで一瞬で届くぞ！」

ネズミくんがスマホのファイル管理アプリから、お父さんのPC（\\192.168.1.15\cheese_share）を指定して「転送」ボタンを押した瞬間、家の中だけで完結する高速な旅が始まります。

1. スマホの判断：自分と同じグループか？（サブネットの判定）
スマホはパケットに宛先を貼り付ける前に、自分の頭の中で計算を行います。

ネズミくんのスマホのIP: 192.168.1.10

お父さんPCのIP: 192.168.1.15

家のネットワークルール（CIDR）: 192.168.1.0/24（/24 は「192.168.1. までが同じなら同じ家」）

スマホは判定します。

「宛先の頭は 192.168.1. だ。僕のIPと完全に同じグループ（同じサブネット）だぞ！この相手は家の中にいる。外の世界へ行く玄関（デフォルトゲートウェイ 192.168.1.1）へ頼る必要はない！」

2. 相手の物理的な名前を探せ（ARPとMACアドレス）
家の中にいると分かったスマホですが、実際にWi-Fiの電波でパケットを正確に届けるには、IPアドレスだけでなく相手の機器固有の番号「MACアドレス（マックアドレス）」が必要です。

スマホは家の中全体に向かって叫びました（ARP：アープ）。

「ブロードキャスト通信！！ IPアドレス 192.168.1.15 を持っている機器（お父さんのPC）はいますか！？あなたのMACアドレスを教えてください！」

この声はWi-Fiを通じて家中の機器に届き、お父さんのPCが返信します。

「私ですよ！私のMACアドレスは AA:BB:CC:11:22:33 です！」

3. スイッチのスマートな交通整理（L2スイッチングとNAT不要）
宛先のMACアドレスを知ったスマホは、パケットをWi-Fiへと飛ばします。

受け取った家庭用ルーターの内部にあるスイッチ（L2スイッチ機能）は大活躍します。

Webサイトへ送る場合（WAN通信）：

「外行きだな。プロバイダのネットワークへ送り出して、IPアドレスも変換（NAT/NAPT）しよう！」

今回の共有フォルダへ送る場合（LAN内通信）：

「宛先はお父さんのPC（AA:BB:CC:11:22:33）か！これは有線LANポート2番に繋がっているね。外のプロバイダやNAT変換へ通す必要は一切なし！そのままお父さんのPCへ直接転送！」

パケットはプロバイダのネットワーク（WAN）へ1バイトも出ることなく、ルーター内部のスイッチを経由して直接お父さんのPCへ吸い込まれていきました。

4. 旅の結末：爆速で保存されたチーズ
「カチャッ（転送完了）」

インターネット（プロバイダ網）を経由せず、家の中のLANだけで届いたため、通信は一瞬で完了しました。

お父さんのPCの画面を開くと、共有フォルダの中に高画質な「特製エメンタールチーズ.jpg」がしっかりと保存されていました。

「おっ、ネズミくん！共有フォルダに写真を入れてくれたんだね。ネットを経由してないから超高速だし、容量制限も気にせず大きな画像が届いたよ！」

お父さんは大喜びで写真を確認しました。
